## 2. 本章定位

- **解决什么问题**：当状态空间很大、线性递推无法满足时空要求时，只递推**在 2 的整数次幂位置上**的值，
  再用「任意整数可表示为若干 2 的幂之和」拼出所需值 `[BOOK] p.39`。
- **书中的说法**：使用倍增要求「递推的问题的状态空间关于 2 的次幂具有可划分性」`[BOOK] p.39`。
- **与前后知识的联系**：
  - 前：`0x01 位运算`、快速幂——书中指出「快速幂其实就是『倍增』与『二进制划分』思想的一种体现」`[BOOK] p.39`。
  - 前：`0x03 前缀和`——序列倍增查找用前缀和做区间和判定 `[BOOK] p.40`。
  - 后：`0x63 树的直径与最近公共祖先`——树上倍增（LCA）在该节 `[BOOK] p.39`。
  - 旁：`0x04 二分`——同样是「快速定位」，但倍增在答案为 0/很小时更优 `[BOOK] p.40`。
- **算法前提**：前缀和、比较与循环 `[BOOK] p.40`。
- **学习准备建议**：能手写 ST 表并理解「重叠区间取最值」`[EXTENSION]`。

## 3. 核心知识点

### 3.1 倍增的思想本质

- **为什么需要**：线性递推的空间/时间与状态空间成正比；倍增只算 `2^0, 2^1, 2^2, …` 这些代表位置，
  把复杂度降到对数级 `[BOOK] p.39`。
- **与二进制划分的关系**：任意整数 `k` 可拆成若干个 2 的幂之和，于是「拼」出任意位置的值 `[BOOK] p.39`。
- **成倍扩张 vs 二进制组合**：扩张是「当前长度翻倍」（`p *= 2`），组合是「把若干个 2 的幂拼起来」；
  两者结合才构成倍增算法 `[DERIVED]`。
- **适用条件**：状态可按长度 2 的幂划分并合并（ST 的区间最大值、倍增查找的前缀和） `[BOOK] p.39`。
- **与二分、快速幂的联系** `[DERIVED]`：
  - 快速幂：底数不断平方（成倍扩张）+ 指数按二进制拆分累乘；
  - 二分：每次折半缩小区间，依赖单调性；
  - 倍增：从当前位置「试着跳 2^j 步」，可行就跳、不可行就减半步长——依赖**可加/可合并**且**单调**的判定。

### 3.2 序列前缀和的倍增查找

**模型** `[BOOK] p.39–40`：给定长度 `N` 的数列 `A`（`0 ≤ T ≤ ΣA`），在线回答若干询问：
求最大的 `k`，使 `Σ_{i=1..k} A[i] ≤ T`。

**朴素**：从前向后枚举，每次 `O(N)`；**二分**：预处理前缀和 `O(N)`，每次 `O(log N)`，
但当 `T` 很小时答案 `k` 很小，二分「第一步就检验很长的区间」，反而不如暴力 `[BOOK] p.40`。

**倍增做法** `[BOOK] p.40`：

```
预处理（只做一次，O(N)）：
    S[0] = 0
    for i = 1..N: S[i] = S[i−1] + A[i]

查询(T)：
    p = 1, k = 0
    while p > 0:
        if k + p ≤ N 且 S[k + p] ≤ T:      // 不变量 sum = S[k]，直接比前缀和
            k += p
            p *= 2
        else:
            p /= 2
    return k
```

- `p` 是当前试探的跨度（总是 2 的幂）；
- `k` 是已确认可行的最远位置；
- `sum` 就是 `S[k]`，因此判定可**直接写成 `S[k+p] ≤ T`** `[DERIVED]`，既避免
  `sum + S[k+p]` 的中间加法溢出，也与不变量一致。书中原文用 `sum + S[k+p] − S[k]` `[BOOK] p.40`，
  在 `S` 接近 `long long` 上限时会溢出。
- **不变量** `[DERIVED]`：循环中始终 `S[k] ≤ T`；`k` 单调不减，`p` 到 0 时 `k` 即最大可行位置。
- **预处理与查询分离** `[DERIVED]`：`S` 只在开始建一次 `O(N)`；每次查询只读 `S`，不得重建。
- **复杂度** `[DERIVED]`：
  - 预处理 `O(N)`，只做一次；
  - 单次查询 `O(log k)` 次判定（`p` 成功翻倍、失败折半的二进制计数器分析），
    与答案位置的对数有关、与 `N` 无关；`k = 0` 时一次失败判定即返回，为 `O(1)`。
  - 书中表述为「时间复杂度的级别为答案的对数」`[BOOK] p.40`，这里补充预处理与单次查询的分工。

**前提** `[DERIVED]`：

- `A[i] ≥ 0`，否则前缀和不单调、`k` 的最大性不成立；
- 必须检查 `k + p ≤ N`，否则 `S[k+p]` 越界；
- `T` 可达 `ΣA`，`sum` 需用 `long long`。

### 3.3 Genius ACM（CH0601）

**题意** `[BOOK] p.40`：给定数列 `A` 与整数 `T`，把 `A` 分成尽量少的段，
使每段的「校验值」都不超过 `T`。校验值 = 从段中取 `M` 对（不重复用数）使「每对差的平方」之和最大。

**校验值为什么是首尾配对** `[BOOK] p.40`：应取最大的 `M` 个数与最小的 `M` 个数，
最大配最小、次大配次小……这样平方和最大。

**贪心分段** `[BOOK] p.40`：每段在「校验值 ≤ T」的前提下尽量长，从头顺序分段即可得到最少段数。

**倍增找右端点** `[BOOK] p.40`：固定左端点 `L`，令 `p = 1, R = L`；
检验 `[L, R+p]` 的校验值，`≤ T` 则 `R += p, p *= 2`，否则 `p /= 2`；`p = 0` 时 `R` 为最远右端点。

**复杂度** `[BOOK] p.41`：

- 每个左端点最多循环 `O(log N)` 次，每次对 `O(R−L)` 的一段排序，总 `O(N log² N)`；
- 若用「只对新增部分排序再归并」的增量方式，可降到 `O(N log N)`。

**溢出（区分原题范围与通用实现）** `[DERIVED]`：

- **原题数据范围** `0 ≤ A_i ≤ 2^20`（约 `10^6`）：单对差值 `< 2^21`，平方 `< 2^42 ≈ 4.4×10^12`；
  `M` 对累加在最坏情况下仍远小于 `2^63−1`，**有符号 `long long` 足够**。
- §5.2 的反例用了 `|A_i| ≤ 10^9` 且累加 `1.2×10^19`，这**超出原题范围**，属于
  「通用代码健壮性」的压力测试，不是原题合法数据。若要让实现同样能承受这种输入，
  需用 `__int128` 或提前退出——这正是 §5.2 采用 `__int128` 的理由。
- `unsigned long long` 只是把上限翻倍，**不能**代替溢出分析。

### 3.4 ST 算法

**RMQ 建模** `[BOOK] p.41`：长度 `N` 的数列，在线回答「下标 `l~r` 的最大值」。

**状态** `[BOOK] p.41`：`F[i][j]` 表示从 `i` 开始的 `2^j` 个数的最大值，即区间 `[i, i+2^j−1]`。

**转移** `[BOOK] p.41`：`F[i][j] = max(F[i][j−1], F[i+2^{j−1}][j−1])`，边界 `F[i][0] = A[i]`。

**查询** `[BOOK] p.41`：取 `k = ⌊log₂(r−l+1)⌋`，答案为
`max(F[l][k], F[r−2^k+1][k])`。

**为什么可以重叠** `[BOOK] p.41`：求最大值时，两段只要**覆盖**整个区间即可，重叠不影响结果。
`[DERIVED]` 求和则不成立：重叠部分会被算两次，因此 ST 不能直接用于区间和。

**复杂度** `[BOOK] p.41`：预处理 `O(N log N)`，单次查询 `O(1)`。

**log 的实现** `[BOOK] p.42`：书中直接用 `log(r−l+1)/log(2)`；严格保证 `O(1)` 应预处理
`1..N` 每个长度的 `k`（`O(N)` 时间），避免浮点误差与函数调用开销。

## 4. 算法推导

### 4.1 倍增为什么正确

**按代码过程解释** `[DERIVED]`：`p` 从 1 开始，

- 若 `S[k+p] ≤ T`（能跳），就执行 `k += p, p *= 2`——跨度**翻倍**，继续向后扩张；
- 否则（不能跳），执行 `p /= 2`——跨度**减半**，改试更小的步长。

`p` 取遍 `2^0, 2^1, …` 后开始折半，因此最终 `k` 的二进制展开正是「哪些步长成功跳过」的集合：
每一步要么把当前 `p` 对应的那一位记为 1（成功），要么在失败后转向更低位。
当 `p` 减到 0 时，所有位都已确定，得到的 `k` 是**不超过可行上限的最大前缀长度**。
这与「二进制拆分」一一对应，但过程是**先扩张、后收缩**，不是预先从大到小枚举。

### 4.2 倍增查找的不变量与复杂度

- 不变量：**`S[k] ≤ T`，且 `k` 是当前已确认可行的最长前缀**（`[DERIVED]`）。
  代码只维护 `k` 与 `p`，不单独维护 `sum`——因为区间和直接用前缀和 `S[k]` 表示，
  判定也只用到 `S[k+p]`。
- 终止：`p` 每次失败减半，必到 0；此时不存在更长的可行前缀，否则其二进制最高位会被尝试并成功。
- 复杂度：`p` 的取值序列是「翻倍—折半」的二进制计数器，判定次数 `O(log k)` `[DERIVED]`；
  `k = 0` 时第一次判定失败即 `p = 0`，为 `O(1)`。

### 4.3 校验值首尾配对的正确性

设段内数升序 `x_1 ≤ … ≤ x_n`，要选 `M` 对使 `Σ(a−b)²` 最大 `[DERIVED]`。

**引理 1（极值必可入配对）**：若最大数 `x_n` 未配对，取任一对 `(x_p, x_q)`，
把 `x_q` 换成 `x_n`：新差值 `x_n − x_p ≥ x_q − x_p ≥ 0`，平方和不减。故存在最优配对含极值。

**引理 2（首尾配对最优）**：设 `a ≥ c`、`b ≥ d` 且 `a ≥ b`、`c ≥ d`，则

```
(a−b)² + (c−d)² − [(a−d)² + (c−b)²] = 2(a−c)(d−b) ≤ 0
```

即「大配小」不小于「交叉配」。反复交换，可把任意配对调整为「最大配最小、次大配次小」，
且平方和单调不减，故首尾配对最优。

**引理 3（单调性）**：区间缩短后校验值不增大 `[DERIVED]`——缩短后的集合是原集合的子集，
其任一合法配对也是原集合的合法配对，故原集合的最大值不小于它。这是 §4.4 贪心所需的前提。

### 4.4 贪心分段的最优性

**引理**：若某方案的第一段右端点 `R' < R`（`R` 为从 1 开始的最远可行右端点），
把它扩展到 `R` 不会使后续段数增加 `[DERIVED]`。

理由：由 §4.3 引理 3，区间缩短不会增大校验值。把第一段延长到 `R` 后，原方案中后续各段
被「压缩」到更短的区间上，校验值只减不增，仍然可行；段数不变。故存在与贪心同样好的方案，
「每段尽量长」最优。

### 4.5 ST 查询覆盖性

`k = ⌊log₂ len⌋` ⇒ `2^k ≤ len < 2^{k+1}` `[DERIVED]`：

- 左段 `[l, l+2^k−1]`、右段 `[r−2^k+1, r]`，两段长度都是 `2^k`；
- 左段起点 `l ≤ r−2^k+1`（因为 `len ≥ 2^k`），右段终点 `r ≥ l+2^k−1`，故两段覆盖 `[l,r]`；
- 覆盖即可，重叠无妨（最大值幂等）。

### 4.6 浮点 log 的问题

`log(r−l+1)/log(2)` 在 `r−l+1` 为 2 的幂时可能因浮点误差得到 `k−ε`，向下取整出错 `[DERIVED]`。
稳妥做法是预处理 `lg[len] = ⌊log₂ len⌋`（`lg[i] = lg[i/2] + 1`），查询 `O(1)` 且无误差。

## 5. 代码实现

### 5.1 序列倍增查找 `[DERIVED]`（书中只给流程，未给完整代码）

```cpp
struct PrefixSum {
    vector<long long> S;
    void build(const vector<long long>& A, int n) {   // O(N)，只做一次
        S.assign(n + 1, 0);
        for (int i = 1; i <= n; i++) S[i] = S[i - 1] + A[i];
    }
    int query(int n, long long T) const {             // O(log k)
        int p = 1, k = 0;
        while (p > 0) {
            // 不变量 S[k] <= T：直接比 S[k+p]，避免 sum + S[k+p] 的中间溢出
            if (k + p <= n && S[k + p] <= T) { k += p; p *= 2; }
            else p /= 2;
        }
        return k;
    }
};
```

**溢出反例** `[DERIVED]`：`A = {5×10^18, 3×10^18}`、`T = 8×10^18`。
旧写法在 `k = 1` 时算 `sum + S[2] − S[1]`，其中 `sum + S[2] = 5×10^18 + 8×10^18 = 1.3×10^19 > 2^63−1`，
UBSan 下直接 trap；新写法只比较 `S[2] = 8×10^18 ≤ T`，结果 `k = 2` 正确。

### 5.2 Genius ACM `[DERIVED]`（书中未给完整代码）

```cpp
// 返回该段校验值是否 <= T：__int128 累加，一旦超过 T 立即返回
bool checkLE(const vector<long long>& v, int M, long long T) {
    vector<long long> u = v;
    sort(u.begin(), u.end());
    int pairs = min<int>(M, u.size() / 2);
    __int128 s = 0;
    for (int i = 0; i < pairs; i++) {
        __int128 d = (__int128)u[u.size() - 1 - i] - (__int128)u[i];
        s += d * d;
        if (s > (__int128)T) return false;   // 提前退出
    }
    return s <= (__int128)T;
}

int geniusACM(const vector<long long>& A, int n, int M, long long T) {
    int segs = 0, L = 1;
    while (L <= n) {
        int p = 1, R = L - 1;
        while (p > 0) {
            if (R + p <= n) {
                vector<long long> v(A.begin() + L, A.begin() + R + p + 1);
                if (checkLE(v, M, T)) { R += p; p *= 2; continue; }
            }
            p /= 2;
        }
        segs++; L = R + 1;
    }
    return segs;
}
```

**溢出反例（通用实现的压力测试，超出原题数据范围）** `[DERIVED]`：

`A = {−10^9, −10^9, −10^9, 10^9, 10^9, 10^9, 10^9}`（`n = 7`）、`M = 3`、`T = 10^18`。
整段校验值 `= 3 × (2×10^9)² = 1.2×10^19 > 2^63−1`；旧实现累加溢出后可能误判为可行而返回 1 段，
安全实现返回正确的 **2 段**。

原题 `0 ≤ A_i ≤ 2^20` 的合法数据不会触发这种溢出；这里刻意放大数值，是为了验证
「换一组数据也不能出错」的通用实现。

### 5.3 ST 表 `[BOOK] p.41`（已逐字符核对 p.51 图像）

```cpp
void ST_prework() {
    for (int i = 1; i <= n; i++) f[i][0] = a[i];
    int t = log(n) / log(2) + 1;
    for (int j = 1; j < t; j++)
        for (int i = 1; i <= n - (1 << j) + 1; i++)
            f[i][j] = max(f[i][j - 1], f[i + (1 << (j - 1))][j - 1]);
}

int ST_query(int l, int r) {
    int k = log(r - l + 1) / log(2);
    return max(f[l][k], f[r - (1 << k) + 1][k]);
}
```

> 书中提示：为保证严格 `O(1)`，可预处理 `1..N` 每个长度的 `k` 值 `[BOOK] p.42`。

## 7. 易错点与注意事项

- **倍增查找不检查 `k + p ≤ N`**：`S[k+p]` 越界 `[DERIVED]`。
- **把倍增用于非单调/含负数的前缀和**：`k` 的最大性失效 `[DERIVED]`。
- **`p` 初值与终止条件**：`p` 必须从 1 开始、以 `p > 0` 为循环条件，写成 `p >= 1` 且整除会死循环 `[DERIVED]`。
- **Genius ACM 忘记 `M` 对需要 `2M` 个数**：不足时取到不能取为止 `[BOOK] p.40`。
- **平方和溢出**：原题 `A_i ≤ 2^20` 用 `long long` 足够；若要兼容 `|A_i| ≈ 10^9` 的通用输入，需 `__int128` `[DERIVED]`。
- **ST 用于区间和**：重叠会重复计数，不成立 `[DERIVED]`。
- **ST 查询 `k` 取错**：`k` 必须是 `⌊log₂ len⌋`，取大了会越界 `[DERIVED]`。
- **浮点 `log` 误差**：长度恰为 2 的幂时可能少 1，建议预处理整数 log `[DERIVED]`。
- **倍增查找用 `sum + S[k+p] − S[k]` 判定**：中间加法可能溢出，应直接比 `S[k+p]` `[DERIVED]`。
- **校验值用 `long long` 累加**：多对大差值可达 `10^19`，应 `__int128` 或提前退出 `[DERIVED]`。
- **倍增与二分混淆**：二分依赖单调性折半，倍增依赖「按 2 的幂可合并」`[EXTENSION]`。

## 9. 教学应用建议

> 本节为教学设计建议，**非原书内容** `[EXTENSION]`。

- **适合动画**：`p` 的翻倍/折半与 `k` 的跳跃（二进制计数器）；ST 表的「两段覆盖」高亮。
- **学生最易误解**：倍增=二分；ST 能求区间和；`p` 越界；`M` 对需要 `2M` 个数。
- **适合交互**：给定 `T` 与数组，让学生手动走一遍 `p` 的变化；点击区间看 ST 的两段。
- **值得动态展示的状态**：`p`、`k`、`sum`、`f[i][j]` 表、查询的 `k`。
- **课堂问题**：为什么倍增查找的复杂度与答案的对数有关，而不是与 `N`？为什么 ST 查询可以重叠？
