# 网页端单一入口：闭环验收约定

目标：用户只在现有 ChatGPT 网页聊天讨论需求。ChatGPT 发布 GitHub 任务；本地 DSH 自动执行与回传；ChatGPT 自动审查。不通过时发布下一轮任务，直到通过后在原聊天询问下一个需求。一次性配置不应变成每轮人工转发。

## 接通前置条件

1. 本地桥接器使用独立、固定安装目录运行，不依赖用户或 DSH 正在切换分支的教学仓库。电脑保持在线，具备已验收的启动/恢复入口。
2. 事先批准根任务的文件范围、资料读取范围、测试集合、有效期、最大 CLI 次数和返工轮数（建议最多三轮）。同一范围内返工不重复要求用户授权；范围扩大、凭据缺失、不可逆操作或次数用尽才询问用户。
3. 教材任务需要另行接通本机材料/页面核对流程，不能用当前仅文本输入的执行器冒充已能阅读扫描 PDF。
4. 网站任务需要受限执行环境、固定 build/浏览器交互测试和可审查截图。桥接器单元测试不能代替网站验收。
5. ChatGPT 网页端必须配置并实测审查触发；普通 PR/Issue 评论不保证自动唤醒聊天。这里不能用 Codex 的本地定时任务替代 ChatGPT 独立审查。

## 状态与返工

单个根任务只允许一条串行执行链。首轮与返工均有唯一 task_id；每轮绑定实际输入完整 SHA、上一轮任务和精确白名单。返工基线使用上轮已推送 local-dsh 分支/commit，避免从旧 dev 重复生成。输出保持独立 Draft PR，不改 main，不自动合并。

执行结束先为 reported，不能由 DSH 自评 done。ChatGPT 审查实际 commit、diff、确定性测试和适用的视觉证据；审查意见必须绑定同一 SHA，不能批准新提交的旧审查。

- 通过：发布绑定 task_id/commit 的 LOCAL-DSH-REVIEW，verdict=accept；本地 ACK done。网页端报告完成，并询问下一个需求。通过不等于自动合并。
- 返工：发布 verdict=rework；将问题写入 GitHub，使用新 task_id、实际结果 SHA、原范围或更窄范围发布下一轮 LOCAL-DSH-TASK。保留根任务关联和轮数，不能无限创建新 ID 绕过配额。
- 异常：限定次数内只重试幂等回传；模型执行崩溃不盲目重跑。达到上限或不能核实资料时回到原聊天解释阻碍并询问用户。

当前代码已接入根任务家族配额、授权继承及新需求基于最终通过提交继续开发的协议，并通过自动测试；网页触发与整条真实返工循环尚未通过验收，不应启用完整无人值守流程。

## 网页审查任务的一次性配置规格（尚未部署）

在原聊天“算法可视化网页改版”配置 ChatGPT 审查任务，使用该聊天已有 GitHub 连接。范围仅 RobateV/algorithm-visualizer 的本地 DSH 结果 PR，明确排除旧云端 lesson/dsh 任务和本桥接器基础设施 PR。

可用时选择 GitHub PR 活动事件；实际账户不支持时选择定时检查同一聊天，明确延迟。两者均需真实验证一次自动唤醒、GitHub 写入与同聊天交付；不能只看到任务创建成功就宣称闭环完成。

每次运行：读取未审查的新结果，核验任务身份、输入 SHA、结果 SHA 与范围；没有新结果不调用开发模型；有新结果独立审查并只为该 SHA 写一次结论。若不通过，在既定配额/范围内发布下一轮；通过则完成根任务并询问用户下一项。处理自己发布的评论不得触发重复任务或重复审批。

OpenAI 官方文档说明，支持的 GitHub 事件触发取决于计划与工作区授权，并在网页端/移动端提供；网页定时任务可回到同一聊天。当前 Codex 工具未提供本账户网页端此项配置能力，不能据此断言已部署或账户一定支持：https://learn.chatgpt.com/docs/automations

## 本轮修复验证

先复现“validate 等待中 stop 后仍发生 push/PR/结果发布”：旧实现发生三次后续写调用，回归测试失败。修复后，每个远程写入入口重新检查 signal、STOP、PAUSED、本地策略和授权文件；API 查询返回后在 POST 前再次检查，Git/HTTP 写入接入取消信号与超时。

已经发出的 GitHub 请求/正在被服务端处理的 push 不能保证撤回；取消阻止后续步骤，下一轮依据真实远程状态恢复。Windows Job 包装器的取消及正常退出后代回收已通过普通和 detached 真实进程测试；它不是低权限文件或网络沙箱。

同时将单任务完整提示词限制为 128 KiB，超限在预留 CLI 调用前拒绝。系统隔离未验收前，自动策略只能修改 Markdown/文本，不能修改可执行代码、测试或构建配置；仍保留默认关闭。文档编辑权限并不意味着教材读取流程已接通。

## 网页实际能力核实

用户授权一次能力查询后，Codex 已通过 send_message_to_thread 向原聊天发送消息，并直接读取到网页 ChatGPT 的回复；已证实“指定聊天收消息并执行一轮回复”可行。未证实本地 DSH 可以直接调用此工具，也未证实无人值守通知链路。

网页当前实际存在 Automations create/notify_parent/peek，工具频率上限为每小时；list_event_sources 实际返回 404，不能确认原生事件触发。原有审查任务只匹配 github-actions[bot]、lesson/dsh-*、标题 DSH，不能代替本地结果审查；原聊天回传绑定仍未验证。本次只读核实，未更改任务。

用户另提出由 DSH 操作本机浏览器向原聊天发送完成通知。已编写默认关闭的 localhost 通知端与本地浏览器扩展，详见 BROWSER-RELAY.md。已验证 HTTP 权限、任务筛选、私有数据排除及 ACK 持久化；浏览器端 DOM 发送尚未实测，不能标为已实现的闭环。当前 Windows Computer Use 技能依赖的 node_repl/@oai/sky 工具入口未向本会话提供，无法代替用户安装浏览器扩展；不得用猜坐标、私有 ChatGPT 接口或绕过登录替代。另一候选是 Codex 仅作为结果中转、由网页 ChatGPT 独立审查；需要单独授权后台消息范围并说明 Codex 额度消耗。两者都不能用一次人工工具消息成功推定为完整闭环。
