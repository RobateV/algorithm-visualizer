# 本机浏览器通知通路（实验版，未完成浏览器验收）

这是一条区别于每小时网页定时任务的候选：本地执行器写入结果 → localhost 通知端 → 浏览器扩展 → 原聊天消息 → 网页 ChatGPT 使用 GitHub 工具独立审查。浏览器仍需登录且原聊天标签页打开。扩展每分钟查询一次本机，不调用模型；没有结果不发消息。发送到网页后会使用网页 ChatGPT 的正常额度。不需要 OpenAI API，也不需要 Codex 每分钟运行模型。

**本版本只通过了本机 HTTP、权限、数据筛选及持久化 ACK 测试。未在用户已登录的真实 ChatGPT 页面验证输入、发送、自动审查和多轮返工，不能标为已接通。** 页面 DOM 是不稳定接口，布局/选择器变化、验证码、登录失效均应停止，不尝试绕过。用户已授权的那一次聊天能力查询不代表此扩展已获发送授权。

## 一次性安装与授权

1. 用户审阅 browser-extension 源码，在正在使用的 Chrome/Edge 扩展管理页加载该文件夹（解压后加载目录）。需要用户手动完成浏览器安装及站点访问权限，本次代码不会自动安装。
2. 在独立固定桥接目录运行 prepare-browser-relay.cmd。它仅生成本机随机中转密钥并启用 localhost 中转配置；不会启用 DSH、push 或 merge。已有配置启用前会保留本地备份。
3. 打开扩展弹窗，导入该目录 `.local-state/browser-relay.json`。此文件含本机密钥，不要上传 GitHub、分享截图或粘贴到聊天。导入后扩展仍关闭。
4. 用户勾选“授权自动向指定聊天发送结果通知”，然后打开且只保留一个目标聊天标签页，启动本地桥接服务。必须实测一次无害通知的发送与浏览器 ACK，之后才讨论真实执行授权。

本地服务只绑定 127.0.0.1:17321；不开放公网监听。服务与扩展都需要各自启用，任一关闭均不能发送。原教学仓库不适合做安装目录，避免 DSH 切换分支导致服务源码消失；可使用固定 runtime 副本，通过 policy.json 的 projectRoot 指向实际项目。该路径不来自 GitHub 评论。

## 权限与传递内容

Chrome 站点访问权限按域显示为 chatgpt.com；内容脚本在聊天页加载消息监听器，收到通知时先严格校验本机配置的目标 ID，只有目标聊天才读取或操作 DOM；后台也只查询该聊天标签页。未申请 cookies、密码、历史记录或其它网站访问权限。本机密钥和私人聊天 ID 仅保存在扩展本机存储及被 Git 忽略的本地配置，不放入页面 DOM、公开源代码或 GitHub 报告。

通知只包含任务标识、状态和固定仓库结果评论链接；不发送教材正文/PDF、OCR、CLI 原始日志、本地路径或凭据。只选择具备 rootTaskId、真实结果 URL 和允许状态的新式任务；旧 smoke/legacy 结果不会被当作新任务发送。来源网页不能直接访问 localhost 通知端：它拒绝普通网页 Origin，并要求随机密钥；扩展后台执行授权请求。

聊天忙碌、页面未加载、输入框已有草稿、多个目标标签页或发送状态不明时停止/等待；不覆盖草稿、不自动登录、不解验证码。输入采用可见页面 DOM，不使用私有 ChatGPT API 或提取会话 Cookie。出现用户消息标记才 ACK；不明时保留本机已尝试标记并阻止盲目重发。标记基于任务+SHA，可能需要人工核实极端会话丢失/页面虚拟化情况，不能承诺绝对恰好一次。

扩展只确认“通知进入聊天”，不把它当作“审查完成”。审查意见必须另外在 GitHub 上绑定 SHA，执行器才接收。ChatGPT 是否实际调用 GitHub、是否按原授权发布下一轮，以及通过后能否在原聊天提问，都仍需真实验收。通知不扩大文件白名单、教材访问、轮数或费用授权。

## 停止与回滚

取消扩展发送勾选即可停止新通知；停止本地桥接服务会关闭 localhost 监听。浏览器扩展和随机本机配置均可由用户移除，原项目/main/旧网页定时任务不受影响。已发送的网页消息无法由本机取消撤回。当前默认没有启用新的真实任务，也没有安装扩展。
