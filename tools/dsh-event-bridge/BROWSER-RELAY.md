# 本机浏览器通知通路（实验版，未完成浏览器验收）

这是一条区别于每小时网页定时任务的候选：本地执行器写入结果 → localhost 通知端 → 浏览器扩展 → 原聊天消息 → 网页 ChatGPT 使用 GitHub 工具独立审查。浏览器仍需登录且原聊天标签页打开。扩展每分钟查询一次本机，不调用模型；没有结果不发消息。发送到网页后会使用网页 ChatGPT 的正常额度。不需要 OpenAI API，也不需要 Codex 每分钟运行模型。

**0.2.0 已验证本机 HTTP、发送领取/许可/ACK、重启恢复与模拟页面保护；尚未在用户已登录的真实 ChatGPT 页面验证发送、自动审查和多轮返工，不能标为已接通。** 页面 DOM 是不稳定接口，布局/选择器变化、验证码、登录失效均应停止，不尝试绕过。跨聊天工具成功写入一次请求不等于网页已启动回复，也不代表扩展获准持续发送。

## 一次性安装与授权

1. 用户审阅 browser-extension 源码，在正在使用的 Chrome/Edge 扩展管理页加载该文件夹（解压后加载目录）。需要用户手动完成浏览器安装及站点访问权限，本次代码不会自动安装。
2. 在独立固定桥接目录运行 prepare-browser-relay.cmd。它仅生成本机随机中转密钥并激活 localhost 通知配置，固定为 24 小时、最多三次通知；不会启用 DSH、push 或 merge。已有配置启用前会保留本地备份。重新激活会改变起始时间，不重放更早的已回传结果；扩展需要重新导入更新后的到期时间。
3. 打开扩展弹窗，导入该目录 `.local-state/browser-relay.json`。此文件含本机密钥，不要上传 GitHub、分享截图或粘贴到聊天。导入后扩展仍关闭。
4. 用户勾选“授权自动向指定聊天发送结果通知”，然后打开且只保留一个目标聊天标签页，启动本地桥接服务。必须实测一次无害通知的发送与浏览器 ACK，之后才讨论真实执行授权。

安装浏览器扩展及持续发送通知需要用户明确授权。当前会话没有 computer-use 所需的 node_repl 工具，不能代替用户点击安装或伪称已安装；不得修改浏览器配置文件或通过私有 ChatGPT 接口绕过这一步。正常运行后不需要每轮复制任务或命令，授权到期、范围扩大或发生异常时仍应停止。

为了只验证浏览器与独立审查、避免启动教材或花费 DSH 调用，可在用户明确授权后执行一次 `node browser-relay.mjs --queue-review`。它只为固定 PR #23 排队基础设施复审，核验源码工作区干净且当前 HEAD 与 GitHub 已发布 PR 分支一致；不伪造 DSH 完成记录、不启用执行器。通知会明确区分基础设施复审和开发任务结果，也占用同一个通知额度。没有发送授权时不得擅自运行此命令。

本地服务只绑定 127.0.0.1:17321；不开放公网监听。服务与扩展都需要各自启用，任一关闭均不能发送。原教学仓库不适合做安装目录，避免 DSH 切换分支导致服务源码消失；可使用固定 runtime 副本，通过 policy.json 的 projectRoot 指向实际项目。该路径不来自 GitHub 评论。

## 权限与传递内容

Chrome 站点访问权限按域显示为 chatgpt.com；内容脚本在聊天页加载消息监听器，收到通知时先严格校验本机配置的目标 ID，只有目标聊天才读取或操作 DOM；后台也只查询该聊天标签页。未申请 cookies、密码、历史记录或其它网站访问权限。本机密钥和私人聊天 ID 仅保存在扩展本机存储及被 Git 忽略的本地配置，不放入页面 DOM、公开源代码或 GitHub 报告。

任务通知只包含任务标识、状态、完整 SHA、固定仓库结果评论链接和固定审查协议；不发送教材正文/PDF、OCR、CLI 原始日志、本地路径或凭据。只选择具备 rootTaskId、真实结果 URL 和允许状态的新式任务，并筛选通知激活后形成的回传记录；旧 smoke/legacy 结果不会被当作新任务发送。通知授权与执行授权分开：执行授权到期不应抹掉已经回传成果的审查通知，但它不能借通知续期或再次启动 DSH。基础设施复审通知只包含固定 PR 和已发布 SHA 的公开链接。来源网页不能直接访问 localhost 通知端：它拒绝普通网页 Origin，并要求随机密钥；扩展后台执行授权请求。

聊天忙碌、页面未加载、输入框已有草稿、多个目标标签页或发送状态不明时停止/等待；不覆盖草稿、不自动登录、不解验证码。输入采用页面 DOM，不使用私有 ChatGPT API 或提取会话 Cookie。

发送顺序为：页面只读准备检查 → POST /claim 持锁持久化唯一 attempt → 填入通知 → POST /permit 再核验本机配置、PAUSED、STOP 和结果身份 → 再查扩展授权、目标页面及草稿未被用户修改 → 点击发送 → 出现用户消息标记才带 attempt ACK。ACK 幂等，多个客户端领取同一通知至多一个获准。已点击的网页操作不能原子撤回，最终核验与点击间仍有很短的竞态窗口。

本机 claim 保存在 relay-state.json；浏览器标签页的 sessionStorage 只是补充保护。扩展服务进程、标签页或本机服务重启后，未 ACK 的领取一律视为状态不明，只发 relay-inspect 核对用户消息标记，不再次填入或点击。确认后补 ACK；找不到标记就保留现场，人工核实，不通过超时自动重新发送。页面虚拟化、聊天记录丢失或领取后尚未填写就中断时也可能需要人工处理，不能承诺绝对恰好一次。Chrome 的后台服务进程会终止并丢失全局变量，所以不能仅依赖 checking/sessionStorage 去重，见 [官方生命周期说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

扩展只确认“通知进入聊天”，不把它当作“审查完成”。任务通知明确要求 ChatGPT 发布绑定 task_id/commit 的 LOCAL-DSH-REVIEW；返工任务必须继承教材模式和原授权范围、绑定真实结果分支/SHA，不能用新 ID 重置预算。失败或阻断通知只要求说明阻碍，不要求发布 accept 或自动重跑。ChatGPT 是否实际调用 GitHub、是否按原授权发布下一轮，以及通过后能否在原聊天提问，都仍需真实验收。GitHub 同一账号的评论无法从身份上证明由 ChatGPT 生成；程序不会自行发布独立审查或 ACCEPT。

## 停止与回滚

取消扩展发送勾选即可停止新通知；`node browser-relay.mjs --disable` 会备份并撤销本机通知授权，运行中的服务也会在请求时复核。暂停/停止本地服务同样阻止最终发送许可。双击 status-local-dsh-bridge.cmd 现在同时显示本机通知的到期、额度及状态不明数量，不打印中转密钥，也不把本机状态当成浏览器安装证明。

浏览器扩展和随机本机配置均可由用户移除，原项目/main/旧网页定时任务不受影响。已发送的网页消息无法由本机取消撤回。当前默认没有启用新的真实任务，也没有安装扩展。
