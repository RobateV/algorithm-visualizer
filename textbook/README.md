## 5. OCR 识别误差（重要）

本 OCR 由 Windows 内置识别引擎（`zh-Hans-CN`）逐页生成，**未经人工逐字校对**，已知问题包括：

| 现象 | 示例 |
| --- | --- |
| 数学符号失真 | `−1` 被识别为「一 1」，`≤` / `≥` 错乱 |
| 代码运算符不可信 | `while (l < r)` 可能变成 `while 0 < r)` |
| 上下标丢失 | 幂次、下标常被压平成普通数字 |
| 表格错位 | 单元格内容串行 |
| 页眉页脚混入正文 | 每页开头的「基本算法」、页码等 |
| 全角/半角混用 | 括号、逗号、分号不一致 |

因此：

- **公式、代码、上下标一律以 `original/` 中的 PDF 页面图像为准**，OCR 只作检索与定位；
- 已知存在明显缺陷的页面，在对应小节的标题下用 `> [?]` 标出，并在标题尾注释缺陷编号（如 `OCR-009`）；
- 未标 `[?]` 不代表该页无误，只表示**尚未发现**已知缺陷。

`docs/knowledge-base/source-map.md` 中的 `OCR-001`~`OCR-011` 是这些缺陷的登记表。

## 6. 后续章节如何更新

1. 新增章节 OCR：在 `textbook/ocr/` 下按 `0xNN-章节名.md` 命名，同样按印刷页分节并标注 PDF 页；
2. 若发现某页 OCR 有明显错误，在该页小节加 `> [?] 说明`，并在 `source-map.md` 追加一条 `OCR-0xx`；
3. 知识库章节文档引用原文时，写 `[BOOK] p.xx`，必要时给出 `textbook/ocr/...md` 的具体小节链接；
4. 不要修改已有 OCR 正文来「修好」它——OCR 是机器结果，纠错应写在知识库文档或 `[?]` 注释里，
   保持 OCR 与扫描件的一一对应。

## 7. 与知识库的关系

- `textbook/` = **原始材料**（扫描件 + 机器 OCR）；
- `docs/knowledge-base/` = **整理后的知识**（带 `[BOOK]` / `[DERIVED]` / `[MY-NOTE]` 标记）。

两者分工明确：前者用于核对原文，后者用于教学与开发。
